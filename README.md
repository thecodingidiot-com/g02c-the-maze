# g02c-the-maze

Companion repository for **g02c — The Maze** at
[thecodingidiot.com](https://thecodingidiot.com).

The same engine as
[g02a](https://github.com/thecodingidiot-com/g02a-the-platformer) and
[g02b](https://github.com/thecodingidiot-com/g02b-the-stakes) — tile map,
sprite sheet, collision, camera — with gravity removed, movement opened to
four directions, and one deliberate subtraction: **the camera stops
following you.**

## Follow your journey

Building it independently? Here is the brief.

A top-down maze rendered **one screen at a time**. A room is exactly
25×19 tiles at 32 pixels — 800×608, which is the window — so the view
never straddles two rooms. Walk through a doorway and the whole screen
changes: the room you came from is not scrolled away, it is gone.

That single decision is the game. A camera that follows keeps your sense
of place for you, because the wall you just passed is still on screen. A
camera that snaps hands the job back to you, and the only place the
connection between two rooms exists is in your head. You are never shown
a map.

- **`map.c`** — loads a maze of rooms and refuses one that is not a whole
  number of them, since a half-room strip is a screen the camera could
  never rest on.
- **`camera.c`** — holds a *room*, not a pixel offset. The whole
  difference between this and g02a is in that struct.
- **`player.c`** — four-way movement, no gravity, no jump. Collision is
  resolved one axis at a time so you slide along a wall instead of
  stopping dead against it.
- **`render.c`** — draws exactly one room, with bounds that come from the
  room rather than from a scroll position, so it cannot show a
  neighbouring room by accident.

| File | Contents |
| --- | --- |
| `main.c` | SDL2 setup, the game loop, cleanup |
| `map.c` / `map.h` | the room grid, tile lookup, the loader |
| `player.c` / `player.h` | four-way movement and axis-separated collision |
| `camera.c` / `camera.h` | which room you are in |
| `render.c` / `render.h` | one room, one player |
| `gen_maze.py` | generates `fixtures/maze1.txt`; deterministic, BFS-verified solvable |
| `gen_assets.sh` | generates the tileset and sprite sheet |

## Building the solution

```bash
cd solution
make -C libtci re
bash gen_assets.sh
make re
./maze ../fixtures/maze1.txt
```

Controls: arrow keys or `h`/`j`/`k`/`l` to move, Escape or `q` to quit.
Find the yellow marker.

---

## The maze itself

`fixtures/maze1.txt` is generated by `gen_maze.py`, not drawn by hand: a
3×3 grid of rooms, joined by doorways carved through shared walls along a
spanning tree plus two extra links, so the maze is connected without
being a single corridor. The seed is fixed, so the committed fixture is
stable and its diff is reviewable, and the generator **BFS-verifies that
the exit is reachable** before writing anything.

Regenerate it with:

```bash
cd solution && python3 gen_maze.py
```

## What the tester checks

**Build** — the game compiles and links with zero warnings.

**A standalone logic tester** — `map.c`, `player.c` and `camera.c`
compiled and linked with `libtci` alone: no `-lSDL2`, no `-lSDL2_image`,
no display of any kind. They include SDL2 headers for `Uint8` and the
scancode constants but call no SDL function, which is what makes a
headless tester possible. It asserts real numbers:

- the maze loads as 75×57 tiles, and that is 3×3 rooms
- a map that is *not* a whole number of rooms is refused
- the camera starts in the room holding the player, and a room origin is
  always room-aligned
- moving inside a room reports no change; crossing a boundary reports it
  exactly once, and a second look at the same position reports nothing
- a wall stops movement into it, and pressing into a wall *still slides
  along it* — the property that separating the two axes buys

**`maze`** — runs its event loop for two seconds under
`SDL_VIDEODRIVER=dummy` without crashing. The renderer falls back to
software when no accelerated one exists, so this smoke test exercises a
real renderer and real texture loads rather than passing because a NULL
renderer made every draw call a no-op.
